# Replayfy RN example

Minimal app exercising `react-native-replayfy`: `start`, `identify`,
`track`, `screen`, `getSessionId`, JS network/console/error capture, and
`<ReplayMask>`.

## Verify JS integration (no native build needed)

```sh
npm install
npm run typecheck          # App.tsx type-checks against the package
npm run bundle:android     # Metro bundles the whole graph incl. the SDK
```

## Run on a device (full native build)

The native projects (`android/` + `ios/`) are generated by the RN CLI;
generate them once, then link the local native SDKs.

### Android
1. Publish the native Android SDK to your local Maven repo:
   ```sh
   cd ../../replay-android-sdk && \
     JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home \
     ./gradlew :sdk:publishToMavenLocal
   ```
2. Ensure the app's `android/build.gradle` repositories include
   `mavenLocal()`. Autolinking picks up `react-native-replayfy` from
   `node_modules`.
3. Point `ingestUrl` at the host from the emulator: `http://10.0.2.2:4000`.
4. ```sh
   export ANDROID_HOME=$HOME/Library/Android/sdk
   $ANDROID_HOME/emulator/emulator -avd replay_smoke &
   npm run android
   ```

### iOS
Requires CocoaPods (`sudo gem install cocoapods`). Add a local pod entry
to the app's `Podfile` so the bridge resolves the SDK:
```ruby
pod 'Replay', :path => '../../replay-ios-sdk'
```
Then `cd ios && pod install && cd .. && npm run ios`. Use
`http://127.0.0.1:4000` for `ingestUrl` on the simulator.

## What to expect on the dashboard

After launch, `Replay.start` boots the native engine → `POST
/v1/mobile/start`, and the session appears live. Tapping the buttons
emits a `purchase` event, a captured network call, and a console log; the
card field renders masked in playback.
